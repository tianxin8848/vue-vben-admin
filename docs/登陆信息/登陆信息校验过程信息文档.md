# 登陆信息校验过程信息文档

## 一、问题背景

在报销模块的接口测试中，发现审批记录接口 `GET /api/v1/claims/approvals/records/my` 返回的数据中，部分报销记录的 `amount_hkd`（折算港币金额）字段为 `null`，未自动计算港币换算金额。

### 问题示例

```json
[
  {
    "id": "6a715618003ce0ca145e686f",
    "claim_request_id": "6a715618003ce0ca145e686e",
    "action": "submitted",
    "operator_id": "6a2f6acd8d8c88ae7d154c29",
    "operator_username": "lin",
    "employee_region": null,
    "claim_reason_code": "餐饮报销",
    "amount": 88.0,
    "currency": "CNY",
    "amount_hkd": null,
    "approval_status_after": "pending",
    "created_at": "2026-08-04T03:01:44.870000Z"
  }
]
```

> 现象：CNY 报销的 `amount_hkd` 为 `null`，但此前 HKD 报销的 `amount_hkd` 有值（如 `245209.0`）。

## 四、根因分析

### 后端代码定位

问题出在后端 [claim_service.py](file:///Users/xi/Documents/github/7-13/oa/app/services/claim_service.py#L97-L112) 的 `_normalize_amount_hkd` 方法：

```python
async def _normalize_amount_hkd(
    self, amount: float, currency: str, employee_region: Optional[str]
) -> tuple[Optional[float], Optional[float]]:
    if str(employee_region or "").strip() != "香港":   # ← 关键判断
        return None, None
    options = await self.get_claim_options()
    normalized_currency = str(currency or "").strip().upper()
    rate = None
    for item in options.get("claim_currencies") or []:
        if str(item.get("currency_code") or "").strip().upper() == normalized_currency:
            try:
                rate = float(item.get("to_hkd_rate"))
            except (TypeError, ValueError):
                rate = None
            break
    if rate is None:
        return None, None
    return rate, round(amount * rate, 2)
```

### 逻辑说明

1. **第 98 行**：判断 `employee_region` 是否等于 `"香港"`
   - 如果**不是**香港，直接返回 `(None, None)`，跳过换算
   - 如果**是**香港，继续查找汇率并计算

2. 该方法在 [claim_service.py#L226-L230](file:///Users/xi/Documents/github/7-13/oa/app/services/claim_service.py#L226-L230) 创建报销时被调用：

```python
exchange_rate_to_hkd, amount_hkd = await self._normalize_amount_hkd(
    payload.amount,
    normalized_currency,
    current_user.get("region"),   # ← 传入用户地区
)
```

### 验证结论

| 用户 | region | 是否换算港币 | 说明 |
|---|---|---|---|
| lin（之前） | `null` | ❌ 不换算 | region 为空，跳过换算 |
| lin（现在） | `香港` | ✅ 自动换算 | 88 × 1.09 = 95.92 |
| tianxin | `中国大陆` | ❌ 不换算 | 非香港地区，跳过换算 |
| admin | `null` | ❌ 不换算 | region 为空且无报销权限 |

**结论：lin 用户之前 region 为 null 导致港币未换算；现在 region 已修正为 `"香港"`，港币换算正常。tianxin 的 region 为 `"中国大陆"`，按业务规则不参与港币换算。**

## 五、修复建议

### 方案一：确保需要换算的用户 region 为 "香港"（推荐）

将需要港币换算的用户 `region` 设置为 `"香港"`：

```
region: null  →  region: "香港"
```

当前状态：
- ✅ lin 用户 region 已为 `"香港"`，换算正常
- ⚠️ 历史 CNY 记录（region 为 null 时创建的）的 `amount_hkd` 仍为 null，需要的话可重新创建或补录

### 方案二：调整后端换算逻辑（如需支持非香港地区）

如果业务需要所有地区都进行港币换算，修改 [claim_service.py#L98](file:///Users/xi/Documents/github/7-13/oa/app/services/claim_service.py#L98) 的判断条件：

```python
# 修改前
if str(employee_region or "").strip() != "香港":
    return None, None

# 修改后（所有地区都换算）
# if not employee_region:  # 或直接删除该判断
#     return None, None
```

> ⚠️ 此方案需确认业务规则，港币换算是否仅适用于香港地区员工。
