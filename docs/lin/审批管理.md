## 三、异常详情

### P0 — 接口直接报错（Critical）

#### P0-1：`GET /api/v1/me/leave-requests/approval-records` 返回 400 Bad Request

**复现命令：**
```bash
curl -b /tmp/cookies_lin.txt "http://10.254.253.187:8999/api/v1/me/leave-requests/approval-records"
```

**返回响应：**
```http
HTTP/1.1 400 Bad Request
content-type: application/json

{
  "detail": "5 validation errors for LeaveApprovalRecordResponse\n
  leave_request_id\n    Field required [type=missing, input_value={'id': '6a7edca1cab3dcf5a...', 'amount_hkd': 88.88}, input_type=dict]\n
  leave_type\n    Field required ...\n
  session\n    Field required ...\n
  start_date\n    Field required ...\n
  end_date\n    Field required ..."
}
```

**问题分析：**
- 当 `lin` 账号有相关记录时，接口返回 400，响应模型 `LeaveApprovalRecordResponse` 校验失败。
- 校验提示的 `input_value` 中含 `amount_hkd` 字段，这是**报销记录**的字段，说明后端查询的是 claim 表，却用 leave 模型序列化，导致字段对不上。
- 缺失的 5 个必填字段：`leave_request_id`、`leave_type`、`session`、`start_date`、`end_date`。
- 同一接口对 `admin`、`tianxin` 账号返回 200 `[]`（因为这两个账号无相关记录，未触发序列化）。

**修复建议：**
1. 检查 `/api/v1/me/leave-requests/approval-records` 的查询逻辑，确认查询的是 `leave_approval_record` 表，而非 `claim_approval_record`；
2. 补全响应模型所需字段，或在查询时 join `leave_request` 表以填充 `leave_request_id`、`leave_type`、`session`、`start_date`、`end_date`。

### P1 — 业务逻辑缺陷（High）

#### P1-1：申请人可审批自己的报销

**复现命令：**
```bash
curl -b /tmp/cookies_lin.txt -X PATCH "http://10.254.253.187:8999/api/v1/claims/6a7ec57d469a454db91fd8a4/approval" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "approval_status=approved&review_comment=test"
```

**返回响应：** 200 OK，审批通过，状态由 lin（level 1）流转到 dsadas（level 2）。

**问题分析：**
- 该报销 `employee_username = "lin"`（申请人为 lin），同时 `approval_chain[0].username = "lin"`（第一级审批人也是 lin）。
- 调用 PATCH 接口时，lin 既作为申请人又作为审批人，成功批准了自己的报销。
- 通用审批系统的合规要求是「申请人不能审批自己的单据」。

**修复建议：**
- 后端 `review_claim_request` 接口在执行审批前应校验 `current_user.id != claim.employee_id`，若相等则返回 403 Forbidden。

### P2 — 数据质量与设计不一致（Medium）

#### P2-1：聚合 `currency` 字段出现非 ISO 货币码 `CNY+HKD`

**复现接口：** `GET /api/v1/me/claims/approvals`

**异常数据（claim id `6a7ec57d469a454db91fd8a4`）：**
```json
{
  "id": "6a7ec57d469a454db91fd8a4",
  "amount": 0.0,
  "currency": "CNY+HKD",
  "exchange_rate_to_hkd": null,
  "amount_hkd": null,
  "employee_region": "香港",
  "items": [
    {"amount": 111.0, "currency": "CNY",  "amount_hkd": 120.99},
    {"amount": 50.0,  "currency": "HKD",  "amount_hkd": null},
    {"amount": 200.0, "currency": "HKD",  "amount_hkd": null},
    {"amount": 123.0, "currency": "CNY",  "amount_hkd": null}
  ]
}
```

**问题分析：**
- 当报销含多种币种明细时，外层 `currency` 字段被拼接成 `"CNY+HKD"`，不是有效的 ISO 4217 货币码。
- 外层 `amount = 0.0`、`amount_hkd = null`，明细之间无法简单相加，缺少统一的折算总额。
- 同一问题在 `GET /api/v1/me/claims/approval-records` 中也出现（`amount=0.0`、`currency=CNY+HKD`、`amount_hkd=null`）。

**修复建议：**
- 多币种报销的外层 `currency` 应为 `null` 或 `"MIXED"`；
- 外层 `amount_hkd` 应为各明细 `amount_hkd` 之和（按当前地区折算规则）。

#### P2-1 补充：`currency = "JP"`（非标准 ISO 货币码）

在 `tianxin` 的审批记录中出现 `"currency": "JP"`，应为 `"JPY"`（日元）。

#### P2-2：报销与请假审批接口的 Content-Type 不一致

| 接口 | 期望 Content-Type | 发错时的响应 |
|------|------------------|--------------|
| PATCH `/api/v1/claims/{claim_id}/approval` | `application/x-www-form-urlencoded` | 422（找不到 `approval_status`） |
| PATCH `/api/v1/leave-requests/{leave_request_id}/approval` | `application/json` | 422（input should be a valid dictionary） |

**修复建议：** 统一两个审批接口的请求格式，推荐都用 `application/json`。

### P3 — 数据一致性细节（Low）

#### P3-1：明细 `amount_hkd` 在香港地区下仍为 null

**接口：** `GET /api/v1/me/claims/approvals`，claim `6a7ec57d469a454db91fd8a4`（`employee_region = "香港"`）。

| 明细 item_id | currency | amount | exchange_rate_to_hkd | amount_hkd | 期望 |
|--------------|----------|--------|---------------------|------------|------|
| 64cdcd39… | CNY | 111.0 | 1.09 | 120.99 | ✅ 正确 |
| cb0c8fcd… | HKD | 50.0  | null | null | ❌ 应为 50.0 |
| c5b78825… | HKD | 200.0 | null | null | ❌ 应为 200.0 |
| 393743ea… | CNY | 123.0 | null | null | ❌ 应≈134.07 |

**问题分析：**
- 项目规则约定「员工地区为香港时才执行港币换算」。但同一笔香港报销里，仅第 1 条明细被换算，其余 3 条明细的 `exchange_rate_to_hkd` 和 `amount_hkd` 均为 null，逻辑不一致。

#### P3-2：外层 `exchange_rate_to_hkd` 与 `amount_hkd` 不一致

claim `6a7d56627007e67442af6605`、`6a7d41a07007e67442af65fe`（region=香港、currency=CNY）：
```
"exchange_rate_to_hkd": null,
"amount_hkd": 292.12,   // 268.0 × 1.09 = 292.12，汇率已应用但字段缺失
```
汇率已被用于计算 `amount_hkd`，但 `exchange_rate_to_hkd` 字段仍为 null，前后不一致。
