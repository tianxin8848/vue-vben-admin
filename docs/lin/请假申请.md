## 一、接口总览

请假模块共 **20 个接口**，分三类：

| 分类 | 数量 | 权限要求 | 说明 |
|------|------|---------|------|
| 员工端 `/api/v1/me/leave-requests/*` | 7 | `employee_leave`（部分仅需登录） | 我的请假、年假、待审、审批记录、部门请假、创建、撤回 |
| 管理端 `/api/v1/leave-requests/*` | 8 | `leave_calendar`（审批仅需登录+当前审批人） | 全部请假、单条、日历、筛选项、审批、地区假期 |
| 请假流程 `/api/v1/leave-workflows/*` | 5 | 管理端 | 流程的增删改查与元数据 |

## 二、员工端接口（7 个）

### 1. 列出我的请假

```
GET /api/v1/me/leave-requests
```

无参数。返回当前用户全部请假记录数组。

**测试结果**：200 ✅（lin 账号 6 条记录）

**响应字段（LeaveRequestResponse）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 请假 ID |
| `employee_id` / `employee_username` / `employee_name` | string | 申请人信息 |
| `employee_department` / `employee_region` | string/null | 部门、地区 |
| `leave_type` | enum | `annual` / `personal` / `sick` / `lieu` / `long` |
| `approval_status` | enum | `pending` / `approved` / `rejected` / `withdrawn` |
| `approval_chain` | array | 审批链（多级，含 `user_id`/`username`/`full_name`） |
| `current_approver_id` | string/null | 当前待审人（终态为 null） |
| `approval_history` | array | 审批历史（含 `action`/`comment`/`at`） |
| `session` | enum | `full_day` / `morning` / `afternoon` |
| `start_date` / `end_date` | date | 起止日期 |
| `date_keys` | array | 展开的每一天日期 |
| `reason` / `handover_to` | string/null | 请假事由 / 交接人 |
| `created_at` / `updated_at` | datetime | 时间戳 |

### 2. 创建请假

```
POST /api/v1/me/leave-requests
```

**请求体（LeaveRequestCreate）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `leave_type` | enum | ✅ | `annual` 年假 / `personal` 事假 / `sick` 病假 / `lieu` 调休 / `long` 长假 |
| `start_date` | date | ✅ | 开始日期 |
| `end_date` | date | ✅ | 结束日期 |
| `session` | enum | 否 | 默认 `full_day` |
| `reason` | string(≤500) | 否 | 请假事由 |
| `handover_to` | string(≤100) | 否 | 交接人 |
| `regional_holiday_mode` | enum | 否 | `exclude` 排除地区假期 / `include` 包含 |
| `employee_id` | string | 否 | 留空 = 给自己请假 |

**测试结果**：201 ✅，创建即进入 `pending`，`current_approver_id` = 审批链第一级。

**⚠️ 日期冲突检查**：若与已有 `pending`/`approved` 请假日期重叠，返回 **409**：
```json
{"detail": "Leave dates conflict with an existing pending or approved request (2026-08-24)."}
```
同一人同一日期不能重复请假。

### 3. 我的年假汇总

```
GET /api/v1/me/leave-requests/annual-leave/summary?year=2026
```

**参数**：`year`（必填，2000–2100）

**测试结果**：200 ✅

```json
{"year": 2026, "region": "香港", "entitlement_days": 16.0, "used_days": 0.0, "available_days": 16.0}
```

### 4. 我部门的请假

```
GET /api/v1/me/leave-requests/department
```

无参数。返回当前用户同部门（按 `department` 精确匹配）同事的请假。

**测试结果**：200 ✅（香港运营团队 5 条）

### 5. 我的待审请假

```
GET /api/v1/me/leave-requests/approvals
```

无参数。返回当前用户作为审批人、处于 pending 的请假（含全部审批链信息）。

**测试结果**：200 ✅（当时 0 条，返回 `[]`）

### 6. 我的审批记录

```
GET /api/v1/me/leave-requests/approval-records
```

无参数。返回当前用户作为**操作人（approver）或申请人**的所有审批记录，含审批前后的状态变化。

**测试结果**：200 ✅（lin 相关 11 条）

**响应字段（LeaveApprovalRecordResponse）关键字段：**

| 字段 | 说明 |
|------|------|
| `leave_request_id` | 对应请假 ID |
| `action` | `submitted` / `approved` / `rejected` / `withdrawn` |
| `operator_role` | `approver` / `applicant` 等 |
| `approval_status_before` / `approval_status_after` | 审批前后状态 |
| `current_approver_id_before` / `after` | 审批人流转 |
| `is_flowing` | 是否流转到下一级 |

### 7. 撤回请假

```
PATCH /api/v1/me/leave-requests/{leave_request_id}/withdraw
```

**⚠️ 请求体必填（LeaveRequestWithdraw）**，空请求会 422：

```json
{"withdraw_comment": "撤回原因"}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `withdraw_comment` | string(≤500) | 否 | 撤回备注（body 本身必须传） |

**测试结果**：200 ✅，状态变为 `withdrawn`，`current_approver_id` = null，审批历史新增 `action: withdrawn`。

**⚠️ 撤回是终态**：请假没有 draft 概念，**撤回后不能重新提交**（无 submit 接口），需要修改内容只能重新创建一条新请假。

## 三、管理端接口（8 个）

### 1. 列出全部请假（过滤）

```
GET /api/v1/leave-requests
```

**查询参数（均可选）：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `year` | int | 年份过滤 |
| `team` | string | 团队过滤 |
| `region` | string | 地区过滤 |
| `employee_keyword` | string | 员工关键字 |
| `approval_status` | enum | `pending` / `approved` / `rejected` / `withdrawn` |

**测试结果**：200 ✅（`?year=2026&approval_status=pending` 返回 4 条）

### 2. 读取一条请假

```
GET /api/v1/leave-requests/{leave_request_id}
```

申请人或同部门同事只读（需 `employee_leave`）。

**测试结果**：200 ✅

**⚠️ 注意**：员工端**没有** `GET /me/leave-requests/{id}` 单条读取接口，员工查看单条详情需复用此管理端接口（后端校验申请人/同部门权限）。

### 3. 审批请假

```
PATCH /api/v1/leave-requests/{leave_request_id}/approval
```

**请求体（LeaveRequestApprovalUpdate）：**

```json
{"approval_status": "approved", "review_comment": "同意"}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `approval_status` | enum | ✅ | `approved` / `rejected` |
| `review_comment` | string(≤500) | 否 | 审批意见 |

**测试结果：**
- ✅ 当前用户为审批人 + 请假为 pending → **200**，审批通过并流转下一级（`current_approver_id` 变为第二级，状态仍为 `pending`，`is_flowing: true`）
- ⚠️ 请假已撤回/非当前审批人 → **400**（如：对 withdrawn 请假审批返回 400）

**审批机制说明（多级流式审批）：**
- 请假创建时自动匹配流程模板（`/leave-workflows`），生成 `approval_chain` 审批链
- 每级审批人批准后，`current_approver_id` 流转到下一级，`approval_status` 保持 `pending`
- **最后一级批准后才变为 `approved`**；任意一级驳回则变为 `rejected`（终态）

### 4. 请假日历

```
GET /api/v1/leave-requests/calendar?year=2026
```

**参数**：`year`（必填）+ 与列表接口相同的可选过滤（team/region/employee_keyword/approval_status）。

**测试结果**：200 ✅（2026 年共 15 条）

```json
{"year": 2026, "total": 15, "items": [LeaveRequestResponse, ...]}
```

### 5. 日历筛选项

```
GET /api/v1/leave-requests/calendar/meta
```

**测试结果**：200 ✅

```json
{
  "departments": ["深圳研发中心", "香港运营团队"],
  "positions": ["Backend Developer", "Project Manager"],
  "regions": ["中国大陆", "香港"],
  "employees": [{"id", "username", "full_name", "department", "position", "region", "employee_code", "is_active"}]
}
```

### 6. 审批筛选项

```
GET /api/v1/leave-requests/approvals/meta
```

**测试结果**：200 ✅（返回 departments + regions）

### 7. 写入地区假期

```
PUT /api/v1/leave-requests/calendar/regional-holidays
```

**请求体（RegionalHolidayUpsert）：**

```json
{"region": "中国大陆", "date": "2026-10-01", "holiday_name": "国庆节"}
```

**测试结果**：200 ✅，返回完整的地区假期列表。

### 8. 删除地区假期

```
DELETE /api/v1/leave-requests/calendar/regional-holidays
```

**⚠️ 请求体必填（RegionalHolidayDelete），不是 query 参数**：

```json
{"region": "中国大陆", "date": "2026-10-01"}
```

**测试结果**：200 ✅（传 query 参数会 422）

## 四、请假流程接口（5 个）

管理端配置"什么部门/地区/职位的人，按什么顺序由谁审批"。

### 1. 流程列表

```
GET /api/v1/leave-workflows
```

**测试结果**：200 ✅（现有 3 条流程，如"香港运营团队"）

**响应字段：** `id`、`name`、`priority`、`is_active`、`match`（employee_id/department/region/position，均为可空）、`approvers`（数组，每项含 `user_id`/`username`/`full_name`）、`created_at`

### 2. 流程元数据

```
GET /api/v1/leave-workflows/meta
```

**测试结果**：200 ✅（返回 departments / positions / regions / employees 选项，结构与日历筛选项一致）

### 3. 创建流程

```
POST /api/v1/leave-workflows
```

**请求体（LeaveWorkflowCreate）：**

```json
{
  "name": "香港运营团队",          // 必填, 2-50 字符
  "priority": 100,                 // 可选, 默认 100, 数字越小越优先
  "is_active": true,               // 可选, 默认 true
  "match": {"department": "香港运营团队", "region": "香港"},  // 匹配规则, 全部可空
  "approvers": [
    {"user_id": "6a2f...", "username": "lin", "full_name": "lin"},
    {"user_id": "6a62...", "username": "dsadas"}
  ]
}
```

**测试结果**：200 ✅ 创建成功（approvers 按数组顺序组成审批链）

### 4. 更新流程

```
PATCH /api/v1/leave-workflows/{workflow_id}
```

**请求体（LeaveWorkflowUpdate）**：`name` / `priority` / `is_active` / `match` / `approvers` 均可选，传哪个改哪个。

**测试结果**：200 ✅

### 5. 删除流程

```
DELETE /api/v1/leave-workflows/{workflow_id}
```

**测试结果**：200 ✅，返回 `{"deleted": true}`

## 五、状态机与关键机制

### 请假状态流转

```
创建 → pending ──最后一级批准──→ approved
              ├──任一 级驳回──→ rejected
              └──申请人撤回──→ withdrawn   (终态, 不可恢复)
```

### 与报销模块的关键差异

| 对比项 | 请假 | 报销 |
|--------|------|------|
| 草稿机制 | ❌ 无，创建即提交 | ✅ 有 draft → pending → withdrawn → 新 draft |
| 修改接口 | ❌ 无（PATCH 不存在） | ✅ `PATCH /me/claims/{id}`（改金额/备注） |
| 撤回后 | 终态，需新建请假 | 生成新 draft，可修改后重新提交 |
| 审批方式 | 多级流式（逐级流转） | 单级审批 |
| 日期冲突 | ✅ 409 拦截重复日期 | 无 |

### 测试中发现的后端特点

1. **撤回必须带 JSON body**（哪怕只传 `{}`），否则 422 `Field required`
2. **删除地区假期必须带 JSON body**，query 参数会 422
3. **员工端无单条读取接口**，只有管理端 `GET /leave-requests/{id}`（含员工只读权限）
4. **审批人可审批自己的请假**（lin 既是申请人又是第一级审批人时，PATCH 返回 200 正常流转）——与报销模块相同的发现，是否符合业务规范需后端确认
5. **年假额度按地区计算**：香港地区 lin 2026 年额度 16 天
