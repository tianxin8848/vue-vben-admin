# web-ele 请求链路 / 数据渲染 / 路由体系 说明文档

> 范围：`apps/web-ele`（基于 Vben Admin 5 + Element Plus）的「HTTP 请求 → 后端数据接收 → 数据解包 → 界面渲染」完整链路，以及路由结构与路由相关函数。
> 后端为 FastAPI，接口前缀 `/api/v1`，登录态基于 Cookie（`withCredentials: true`）。

## 1. HTTP 请求层：RequestClient

### 1.1 核心实现

`RequestClient` 是对 `axios` 的轻封装，定义在 [request-client.ts](file:///Users/xi/Documents/github/7-13/vue-vben-admin/packages/effects/request/src/request-client/request-client.ts)。

构造时合并默认配置（[L60-L73](file:///Users/xi/Documents/github/7-13/vue-vben-admin/packages/effects/request/src/request-client/request-client.ts#L60-L73)）：

```ts
const defaultConfig: RequestClientOptions = {
  headers: { 'Content-Type': 'application/json;charset=utf-8' },
  responseReturn: 'raw',
  timeout: 10_000,
};
```

并实例化四个子模块：
- `InterceptorManager` → `addRequestInterceptor` / `addResponseInterceptor`
- `FileUploader` → `upload`
- `FileDownloader` → `download`
- `SSE` → `requestSSE` / `postSSE`（Server-Sent Events，流式接口）

### 1.2 暴露的方法签名（[L96-L172](file:///Users/xi/Documents/github/7-13/vue-vben-admin/packages/effects/request/src/request-client/request-client.ts#L96-L172)）

```ts
get<T>(url, config?)                         // GET
post<T>(url, data?, config?)                 // POST
put<T>(url, data?, config?)                  // PUT
patch<T>(url, data?, config?)                // PATCH
delete<T>(url, config?)                      // DELETE
request<T>(url, config)                      // 通用（内部统一入口）
upload / download / postSSE / requestSSE     // 文件 / 流式

```

`request<T>` 是所有动词方法的统一入口，它把 `axios` 返回的 `AxiosResponse<T>` 直接 `as T` 返回；异常时抛出 `error.response?.data ?? error`（[L156-L172](file:///Users/xi/Documents/github/7-13/vue-vben-admin/packages/effects/request/src/request-client/request-client.ts#L156-L172)）。

### 1.3 query 序列化

`getParamsSerializer`（[L15-L37](file:///Users/xi/Documents/github/7-13/vue-vben-admin/packages/effects/request/src/request-client/request-client.ts#L15-L37)）支持 `'brackets' | 'comma' | 'indices' | 'repeat'` 四种数组序列化格式，底层用 `qs`。

## 2. 应用层请求配置：拦截器、解包、错误处理

[api/request.ts](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/request.ts) 是「业务可改」的请求配置文件，导出两个实例：

```ts
export const requestClient = createRequestClient(apiURL, { responseReturn: 'body' });
export const baseRequestClient = new RequestClient({ baseURL: apiURL, withCredentials: true });
```

- `apiURL` 来自 `useAppConfig(import.meta.env, import.meta.env.PROD)`，开发环境即 `.env.development` 中的 `VITE_GLOB_API_URL=/api/v1`。
- `withCredentials: true`：携带 Cookie，登录态走 Cookie 会话而非 Authorization 头。
- `baseRequestClient`：不带业务拦截器，仅用于登出等特殊接口（见 [core/auth.ts L61](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/core/auth.ts#L61) `logoutApi`）。

### 2.1 请求拦截器（[L32-L37](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/request.ts#L32-L37)）

只做一件事：注入国际化语言头。

```ts
client.addRequestInterceptor({
  fulfilled: async (config) => {
    config.headers['Accept-Language'] = preferences.app.locale;
    return config;
  },
});
```

> 注意：项目未在请求拦截器里手动注入 `Authorization`，token 由浏览器 Cookie 自动携带。

### 2.2 响应拦截器①：解包 + 401 重登（[L39-L66](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/request.ts#L39-L66)）

```ts
client.addResponseInterceptor({
  fulfilled: (response) => {
    const rawData = response.data;
    if (rawData && rawData.data !== undefined) {
      return rawData.data;     // 后端 { ..., data: ... } → 直接取 data
    }
    return rawData;            // 否则原样返回
  },
  rejected: (error) => {
    if (error?.response?.status === 401 && config?.url !== '/auth/login') {
      doReAuthenticate();      // 清 token + authStore.logout()
    }
    throw error;
  },
});
```

**解包约定**：后端只要返回体里存在 `data` 字段，就提取 `rawData.data` 给业务层。因此业务层拿到的就是「纯业务数据」，不再有 `{ code, msg, data }` 外壳。

`doReAuthenticate`（[L24-L30](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/request.ts#L24-L30)）：清除 `accessToken` 并调用 `authStore.logout()`，回到登录页。

> ⚠️ 该文件里还残留大量 `console.warn('[DEBUG][request]', ...)` 调试日志（[L45-L53](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/request.ts#L45-L53)），生产环境应清理。

### 2.3 响应拦截器②：错误提示（[L68-L86](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/request.ts#L68-L86)）

```ts
client.addResponseInterceptor(
  errorMessageResponseInterceptor((msg, error) => {
    const rd = error?.response?.data ?? {};
    let errorMessage = rd?.error ?? rd?.message ?? '';
    // FastAPI 校验错误：detail 可能是数组
    if (!errorMessage && rd?.detail) {
      errorMessage = Array.isArray(rd.detail)
        ? rd.detail.map((e) => e.msg || e.message || '').filter(Boolean).join('；')
        : rd.detail;
    }
    ElMessage.error(errorMessage || msg);
  }),
);
```

兼容三种后端错误格式：`error` / `message` / FastAPI 的 `detail`（数组或字符串），统一用 Element Plus 的 `ElMessage.error` 弹出。

### 2.4 后端标准数据格式

结合 [types.ts](file:///Users/xi/Documents/github/7-13/vue-vben-admin/packages/effects/request/src/request-client/types.ts) 与上述解包逻辑，后端响应体的「标准外壳」为：

```jsonc
{
  "code": 0,            // 业务码（当前解包逻辑未严格校验，仅按 data 字段存在性判断）
  "msg": "ok",
  "data": { ... }       // 业务真实数据；存在该字段即被解包
}
```

错误时（HTTP 4xx/5xx）走 `rejected` 分支，响应体可能是 `{ error }` / `{ message }` / `{ detail }` 之一。

### 3.3 API 函数写法约定

每个模块用 `namespace XxxApi` 声明请求/响应类型，函数命名 `xxxApi` 后缀，内部直接调用 `requestClient`。以 [employees.ts](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/business/employees.ts) 为例：

```ts
export namespace EmployeeApi {
  export interface EmployeeResponse { id: string; username: string; /* ... */ }
  export interface EmployeeCreate { username: string; email: string; /* ... */ }
}

/** 获取员工列表 */
export async function getEmployeesApi() {
  return requestClient.get<EmployeeApi.EmployeeResponse[]>('/employees');
}

/** 创建员工 */
export async function createEmployeeApi(data: EmployeeApi.EmployeeCreate) {
  return requestClient.post<EmployeeApi.EmployeeResponse>('/employees', data);
}

/** 更新员工权限（PATCH，路径参数） */
export async function updateEmployeePermissionsApi(employeeId: string, data: EmployeeApi.EmployeePermissionUpdate) {
  return requestClient.request<EmployeeApi.EmployeeResponse>(
    `/employees/${employeeId}/permissions`,
    { method: 'PATCH', data },
  );
}
```

特征：
- URL 全部以 `/` 开头的相对路径，拼接 `baseURL=/api/v1`。
- 文件上传用 `FormData` + `multipart/form-data` 头，见 [claims.ts createClaimApi](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/business/claims.ts#L108-L112)。
- 类型严格：请求参数、响应数据均有 TypeScript 接口。

### 4.2 代表页面 B：请假申请列表（ElTable + Promise.all）

文件：[views/leave/list/index.vue](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/views/leave/list/index.vue)

数据加载函数 `fetchData`（[L221-L236](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/views/leave/list/index.vue#L221-L236)）：

```ts
async function fetchData() {
  loading.value = true;
  try {
    const [requests, summary] = await Promise.all([
      getMyLeaveRequestsApi(),                  // 请假记录
      getAnnualLeaveSummaryApi(currentYear.value), // 年假汇总
    ]);
    leaveRequests.value = requests || [];
    annualSummary.value = summary;
  } catch {
    leaveRequests.value = [];
    annualSummary.value = null;
  } finally {
    loading.value = false;
  }
}
```

- 并发请求两个接口，减少串行等待。
- 派生数据用 `computed`：`filteredLeaveRequests`（过滤撤回/驳回）、`dayMap`（按日期聚合）、`stats`（统计）。

- 错误提示用 `ElMessage.success/warning/error`。

### 4.3 数据从后端到界面的标准步骤

1. 组件 `onMounted` 或 `proxyConfig.ajax.query` 调用 `xxxApi()`。
2. `requestClient` 发起 axios 请求，经请求拦截器注入 `Accept-Language`。
3. 响应拦截器①把 `{ ..., data }` 解包成纯业务数据。
4. 业务函数返回 `Promise<业务类型>`，组件 `await` 拿到数据。
5. 数据赋给 `ref` / `reactive`；派生数据用 `computed`。
6. 模板里 `v-for` / `vxe-grid data` / `ElTable :data` 渲染；插槽 (`slots.default`) 定制列。
7. 失败时响应拦截器②弹 `ElMessage.error`，组件 `catch` 内可补充业务提示。

### 5.4 路由守卫（[router/guard.ts](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/guard.ts)）

`createRouterGuard` 注册两个 `beforeEach`：

**① `setupCommonGuard`（[L52-L76](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/guard.ts#L52-L76)）**
- `loadedPaths` 记录已访问路径，`to.meta.loaded` 标记是否首次进入。
- 首次进入触发 `startProgress()`，`afterEach` 触发 `stopProgress()`（顶部进度条）。

**② `setupAccessGuard`（[L82-L217](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/guard.ts#L82-L217)）** 核心，函数流程：
1. 命中 `coreRouteNames`：已登录访问登录页则重定向到首页，否则放行。
2. 无 `accessToken`：`meta.ignoreAccess` 放行；否则跳登录页并带 `redirect` query。
3. 已 `isAccessChecked`：直接放行（动态路由只生成一次）。
4. 首次进入受保护页：
   - `fetchUserInfo()`（拿 `module_permissions`）；
   - `fetchMenuListAsync()` 调 [buildRoutesFromPermissions](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/module-permission-map.ts#L264-L360) 生成路由树；
   - admin 用户若 `module_permissions` 为空，授予 4 个核心模块（`user_management` / `system_settings` / `data_migration` / `access_control`，[L150-L167](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/guard.ts#L150-L167)）；
   - `generateAccess({ fetchMenuListAsync })` 生成 `accessibleMenus` / `accessibleRoutes`；
   - 写入 `accessStore` 并 `setIsAccessChecked(true)`；
   - 解析 `redirect` 路径，无法解析则回退 `defaultHomePath`。

守卫里的辅助函数：`dumpRouteTree`（调试打印路由树，[L15-L46](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/guard.ts#L15-L46)）。

### 5.5 访问控制 generateAccess（[router/access.ts](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/access.ts)）

- 当传入 `fetchMenuListAsync` 时**强制 `backend` 模式**（[L17-L19](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/access.ts#L17-L19)）。

- `layoutMap = { BasicLayout, IFrameView }`。
- 调 `generateAccessible(accessMode, ...)` 返回菜单 + 路由。

### 5.6 动态路由生成 buildRoutesFromPermissions（[module-permission-map.ts](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/module-permission-map.ts)）

这是权限路由的真正核心。

**数据来源**：`/auth/me` 返回的 `module_permissions: [{ module_code, can_view, can_create, can_edit, can_delete, can_approve }]`。

**三组路由模板**：

   - `employee_approvals` → `EmployeeApprovals`(`/employee/approvals`)

3. `MANAGEMENT_ROUTE_TEMPLATES`（[L172-L253](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/module-permission-map.ts#L172-L253)）：管理后台子路由，按 module_code 开关
   - `user_management` → `EmployeeManageUsers`(`/employee/manage/users`)
   - `user_management_profile` → `EmployeeManageUserProfile`(`/employee/manage/users/:id/profile`)
   - `leave_calendar` → `LeaveManageAdmin`(`/employee/manage/leave`)
   - `leave_workflows` → `LeaveManageWorkflows`(`/employee/manage/leave-workflows`)
   - `approval_management` → `LeaveManageApprovals`(`/employee/manage/approvals`)
   - `system_settings` → `EmployeeManageSettings`(`/employee/manage/settings`)
   - `data_migration` → `EmployeeManageDataMigration`(`/employee/manage/data-migration`)
   - `access_control` → `EmployeeManageAccessControl`(`/employee/manage/access-control`)

**生成逻辑**（[L264-L360](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/router/module-permission-map.ts#L264-L360)）：
- `canViewModule(code)`：`can_view !== false && can_view !== undefined`，即**白名单 + 默认隐藏**（安全优先）。

```
    └ 成功 → 清空 allEmployees 缓存 + reload（强制重新拉取）
```

## 7. 效率分析与改进建议

### 7.1 优点

- **请求层封装完善**：`RequestClient` 支持 GET/POST/PUT/PATCH/DELETE/upload/download/SSE，覆盖全场景；拦截器链式注册，职责清晰。
- **API 类型严格**：每个模块用 `namespace` 集中类型，函数签名带泛型，IDE 提示与编译期校验友好。
- **动态路由安全优先**：`canViewModule` 默认隐藏未授权模块，admin 空权限时降级到核心模块。
- **列表页体验**：员工列表首次拉取后前端筛选/分页，翻页零请求；请假列表 `Promise.all` 并发拉取双接口。
- **错误提示兼容 FastAPI**：`detail` 数组拼接成中文分号分隔的提示。

### 7.2 问题与改进建议

| 问题 | 位置 | 影响 | 建议 |
| --- | --- | --- | --- |
| 响应解包仅按 `data` 字段存在性判断，未校验 `code` | [request.ts L54-L57](file:///Users/xi/Documents/github/7-13/vue-vben-admin/apps/web-ele/src/api/request.ts#L54-L57) | 业务错误（code≠0 但 HTTP 200）会被当成成功 | 改为 `if (rawData.code === 0) return rawData.data; else throw ...` |

### 7.3 整体评价

链路分层清晰（RequestClient → 应用拦截器 → API 函数 → 组件 → 渲染），类型化与模块化程度高，动态路由基于后端 `module_permissions` 实现，权限控制可靠。主要效率瓶颈在「员工列表全量拉取 + 前端分页」与「大量调试日志未清理」；解包逻辑偏宽松，建议收紧为 `code` 校验以匹配标准 `{ code, msg, data }` 协议。
